# Architecture and verification scope

The existing application is React + TypeScript + Vite, a hash router, Zustand, Tailwind, Recharts and diff. UI components and fiscal editors were reused. Workflow commands are in `src/store.ts`; `src/legislative.ts` normalizes collector fixtures and detects changes; fiscal calculation rules are in `src/fiscalCalculations.ts`. No external credentials are required.

The repository currently has **no API or database**. The only initial legislative source is `src/fixtures/wa-legislation-sample-250.json`. `src/fixtures/workspace-config.json` supplies personas and reference settings; mock assignment scenarios are loaded separately from `assignment-scenarios.json` for each login persona. Packages and implementation tasks start empty. `demo-workspace.json` has been removed. HB 1001 is retained only for parser regression tests. Sessions, committees, bill labels and assignment version bindings are derived from official records. No tax classification, budget inclusion or prior fiscal product is invented as a legislative fact. Collector-shaped hearing simulation overlays add four upcoming meetings on existing bills. Only explicitly marked simulation meeting dates are rebased. Workflows update an in-memory Zustand store; reload/reset restores the JSON files. There is no localStorage. Browser authorization is a demonstration behavior, not a production security boundary.

Production target remains an ASP.NET Core API with EF Core/PostgreSQL, Entra OIDC, background ingestion workers, private document storage and independent AWS-deployable containers. These are not implemented or claimed by this frontend update. The execution environment has a .NET runtime but no SDK or Docker. The current prototype does not establish support for 60 concurrent users, server-side filtering or encrypted sensitive storage.

Recommended next implementation slice: create normalized persistence and server-enforced workflow/authorization, migrate command services from the browser into the API, then replace the fixture loader with versioned REST contracts, if a future scope requires a backend. Keep the LSC provider and external integration adapters separate from domain workflow decisions. Use optimistic concurrency tokens for approval and delivery commands.

Automated domain tests exercise commands and import behavior. Playwright exercises the tracking/publication journey and a phone-width hearing page. Accessibility is improved with dialog focus trapping; complete WCAG certification remains outside this validation.

Fixture normalization is cached once per module load. Source records are cloned for isolated working state on reset; raw import payloads are retained by read-only reference. Bill and version lookup maps use WeakMap caches keyed by immutable arrays, preventing stale indexes after edits/imports. Source sessions and committee picklists are derived from fixtures, and large legislative tables are paginated.
